## 0. 产品一句话与介绍

**一句话定位**：用一句自然语言，替你在安全边界内管好钱——查账、理财、转账、管卡、退订阅。

**产品介绍（80 字）**：

> 《引金据典》是一个 AI 银行智能体。你用大白话说出想法，它自主理解意图、规划并代你完成银行业务操作，每一步都有数据可溯、有权限边界。覆盖账单、理财、转账、卡片、订阅五大场景，还能记住你的习惯、预判你的下一步。

---

## 1. 核心主线（不是拼盘）

五场景共用一份「用户资金事实库」，串成一条资金主线：

```
①账单分析        ②理财操作        ③智能转账        ④卡片管理        ⑤订阅代扣
「钱去哪了」  →  「怎么更值」  →  「该花怎么花」 → 「限额与挂失」 → 「别被偷偷扣」
```

卡片管理是咬合点：订阅走卡、转账受卡限额约束、挂失联动停代扣。

## 2. 用户画像

### 画像 A：张同学（大学生）

- 每月 1500 生活费，月底常余额紧张
- 痛点：不知道自己钱花哪了；被 3 个"忘了的会员"每月扣款；聚餐 AA 收款算不清
- 诉求：一句话看清账单、一键退掉没用的订阅、AA 自动分摊

### 画像 B：林悦（刚工作 1 年白领）

- 有工资卡 + 消费卡，开始买基金
- 痛点：忙到没时间理财；担心"AI 推荐不靠谱"；怕卡被盗刷却不会设限额
- 诉求：风险测评后给匹配的理财参考；卡片限额与挂失一键搞定；推荐要能解释、能关

## 4. 用户习惯画像 + 意图预判推荐模块

### 4.1 采集信号（最小必要集）

| 信号 | 采集方式 | 用途 | 合规说明 |
|---|---|---|---|
| 点击/进入的模块 | 行为埋点 | 判断常驻功能 | 仅行为，不含内容 |
| 查询关键词 | 查询日志（脱敏） | 识别高频需求 | 不含账户敏感字段 |
| 反复查看/中途放弃 | 会话状态 | 识别犹豫/需求未满足 | 本地处理 |
| 操作时间规律 | 时间戳 | 识别周期性需求（如月末查账） | 本地处理 |

验收标准：只采集上表 4 类行为信号，不采集通讯录/定位等非必要个人信息；有显式的"关闭画像"总开关。

### 4.2 意图预判输出形态

输出两类内容，均不主动弹窗打扰，以"待办/推荐"卡片静默呈现：

1. **功能入口推荐**：如"你已连续 3 个月底查账单，已把『月度报告』放到首页"。
2. **热点资料卡片**：如"你刚申购了货基，这里是关于货基风险的 3 篇资料"。

触发阈值：同一行为信号累计 ≥3 次 / 或周期性出现 2 次，才触发一次推荐，避免骚扰。

### 4.3 合规三红线（产品功能级落地）

| 红线 | 落地形态 | 对应宪法条款 |
|---|---|---|
| ① 不构成投资建议 | 推荐卡片固定挂："本推荐基于你的操作习惯生成，不构成投资建议" | R11/红线3 |
| ② 可解释、可关闭 | 每条推荐可点开"为什么推荐我"（展示触发证据）；全局总开关一键关闭 | R11 |
| ③ 不诱导、不代决策 | 推荐只做入口跳转/资料展示；理财申购仍需显式确认 + 风险测评通过 | R11/红线1 |

验收标准：三条红线在 UI 上肉眼可见、可交互；推荐逻辑无任何"自动下单"路径。

## 5. 关键用户旅程（3 条）

### 旅程 1：月底查账 → 退无用订阅（多意图 + 联动）

```
用户："看看这个月我花超了没，顺便把我那两个没用的会员退了。"
Agent：
  [识别] 多意图：查本月账单 + 取消订阅 ×2（依赖：先看账单）
  [执行1] 调用 bill 工具 → 展示分类占比 + 超支提示
  [执行2] 列出订阅清单，标记"已不用但仍在扣"的 2 笔
  [确认卡] "确认取消『视频会员 ¥25/月』和『健身 App ¥30/月』吗？取消后可随时恢复"
用户："确认。"
Agent：[执行] 取消成功 → 回执 + "每月可省 ¥55" → 写审计日志
```

**确认卡点**：取消订阅（L2）需单次确认。

### 旅程 2：卡丢了 → 挂失联动停代扣（跨场景联动）

```
用户："我尾号 8888 的卡丢了，帮我挂失。"
Agent：
  [识别] 意图：挂失卡片（L3 高风险）
  [确认卡] "确认挂失尾号 8888 的卡吗？挂失后该卡交易将立即停止"
用户："确认。"
Agent：
  [执行] 挂失成功
  [联动] "检测到该卡上有 2 笔代扣（视频会员、云存储），是否一并暂停？"
用户："一起暂停。"
Agent：[执行] 2 笔代扣已暂停 → 回执 + 审计
```

**确认卡点**：挂失（L3）二次确认；联动暂停代扣再单独确认一次。

### 旅程 3：风险测评 → 理财申购（红线下"推荐不代决策"）

```
用户："帮我看看有什么适合我的理财。"
Agent：
  [执行] 发起风险测评（3 道题）→ 得出"稳健型"
  [推荐] 列出 3 只匹配产品，卡片带"不构成投资建议"+ 免责
  [解释] 每条可点开"为什么推荐我"（基于测评结果 + 持仓风格）
用户："申购 1 号 5000 元。"
Agent：
  [确认卡] "确认申购『1号产品』¥5,000？历史收益不代表未来，申购后 T+1 确认份额"
用户："确认。"
Agent：[执行] 申购成功 → 回执 + 风险提示 + 审计
```

**确认卡点**：申购（L3）二次确认 + 风险提示；推荐环节绝不自动下单。

验收标准：三条旅程各含至少一次"确认卡"卡点；旅程 2 体现"挂失联动停代扣"；旅程 3 体现三红线。

## 6. 本期不做清单（与理由）

| 不做项 | 理由 |
|---|---|
| 卡片申请 | 涉及开卡资质审核，非核心演示价值，卡片管理以"限额/挂失/联动"体现 |
| 真实资金/真实账户 | 竞赛原型，红线 7 明确禁止接入真实资金 |
| 多语言/多币种 | 国内赛道，超出 4 天工期 |
| 语音输入 | IM 渠道后续扩展，本期以文本对话为主 |
| 完整的金融适当性评估框架 | 以规则约束 + 免责声明覆盖，完整框架超出原型范围 |

验收标准：上表在 PPT/文档中如实呈现，体现"克制"而非"遗漏"。
